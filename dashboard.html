ESP32 Medical Monitor Dashboard

🏗️ System Architecture

📡 Communication Flow

Node A (ESP32) 📱
  ├─ Sensors: DHT11, MPU6050, Heart Rate, Button
  ├─ WiFi → HiveMQ Cloud ☁️ (MQTT over TLS, port 8883)
  └─ ESP-NOW → Node B (Emergency backup) ⚡

Node B (ESP32) 🔒
  ├─ Security: IR Sensor, RFID, Buzzer
  ├─ WiFi → HiveMQ Cloud ☁️ (MQTT over TLS, port 8883)
  └─ ESP-NOW ← Receives from Node A ⚡

HiveMQ Cloud Broker ☁️
  ├─ Port 8883: MQTT over TLS (for ESP32s)
  └─ Port 8884: MQTT over WebSocket (for browsers) 🌐

Your Browser 💻
  ├─ Opens dashboard.html locally (file:// or localhost)
  ├─ MQTT.js library connects via WebSocket (wss://broker:8884)
  └─ Subscribes to: node_a/# and security/# topics

🔄 How Data Flows (Real-time!)

  1. ESP32 reads sensors (every 5 seconds)
  2. ESP32 publishes JSON to HiveMQ Cloud via MQTT
  3. HiveMQ Cloud receives and stores the message
  4. Your browser is subscribed to the same topics
  5. Browser gets message instantly via WebSocket
  6. Dashboard updates UI with new sensor values + animations! ✨

⚡ ESP-NOW Emergency System

Why ESP-NOW? It's a peer-to-peer protocol that works without WiFi/router!

How it works:
1️⃣ When Node A detects emergency (fall, button, vitals)
2️⃣ It sends TWO alerts simultaneously:
    📡 MQTT → HiveMQ Cloud → Your dashboard
    ⚡ ESP-NOW → Node B → Buzzer sounds!
3️⃣ Node B also publishes to MQTT for logging

Result: Even if WiFi dies, the buzzer still sounds via ESP-NOW! 🚨

💡 Why This Setup is Awesome

  • ✅ No local server needed - HTML runs in browser directly
  • ✅ Cloud MQTT = access from anywhere with internet
  • ✅ Real-time updates via WebSocket (not polling!)
  • ✅ Secure - TLS encryption on all connections
  • ✅ Redundant - MQTT + ESP-NOW for critical alerts
  • ✅ Multiple viewers - Share dashboard with anyone
